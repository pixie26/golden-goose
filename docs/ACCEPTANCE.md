## 本轮发现与处理

### 1. 英股便士报价被误标为英镑

Yahoo 的 `GBp` 表示便士。原代码在注册和验证时统一大写，变成 `GBP`，前端又直接把这个单位放在未经换算的数值后面。例如测试输入 `12000 GBp`，原版会显示成 `12000 GBP`，读数含义相差 100 倍。南非报价的 `ZAc` 也会丢失正确大小写。

修复后保留供应商单位，展示优先采用报价自身的币种。已有旧登记在下一次成功获得 Yahoo 行情元数据后修正标签，不缩放数值；真正以 GBP 报价的证券仍为 GBP。修正只允许特定旧的非港美登记，之后用 `quoteUnitVerified` 标记严格识别单位变化。HKD / USD 的身份检查、港币 1:1 和美股固定 8 倍换算均通过回归。

相关文件：`lib/core.mjs`、`lib/quotes.mjs`、`lib/api.mjs`、`public/app.js`、`tests/final-quote-units.test.mjs`。

来源核对：Yahoo 的 [AZN.L 历史行情页面](https://finance.yahoo.com/quote/AZN.L/history/)标记为 GBp。本轮端点测试使用明确设置的模拟返回，未把网页检索等同于部署环境 API 连通验证。

### 2. 弱网下，旧账户响应会把新账户踢回登录页

复现顺序：家长页面发出后台刷新 → 退出 → 登录 Olivia → 原家长响应才返回。旧代码在检查“这是否已经过时的请求”之前，就把响应里的家长身份与当前 Olivia 比较并触发退出。延迟的 401 / 403 同样可能使重新登录的同一账户退出。

修复后，每次登录状态变化更新一个会话代次，过时代次的响应不能覆盖或退出当前账户。当前真实会话过期和跨标签页账户变化仍按原规则要求重新登录。

相关文件：`public/app.js`、`tests/final-ui-audit.test.mjs`。

### 3. 到期定存的提示与实际处理不一致

香港日期已经到期，但计划任务尚未运行时，原页面仍显示“提前赎回”，确认框写“没有利息”，成功提示也只说本金返还。后台原本就能正确支付本金加利息，因此这是界面误导，不是少付利息。

修复后由服务端返回香港银行日期，页面显示“已到期，待入账 / 到期取回”，确认框和成功提示说明返还本息。未到期赎回仍不计利息。回归特意让浏览器日期与银行日期不同，确认页面依据银行日期判断。

相关文件：`lib/core.mjs` 的 `view()`、`public/app.js`、`tests/final-view-audit.test.mjs`、`tests/final-ui-audit.test.mjs`。

### 4. 收盘后的撤单入口和手动报价日期不一致

原页面在收盘后仍给孩子显示“撤单”，但后台会正确拒绝；家长的撤销入口则必须等到交易所当地日期跨日才出现，虽然后台收市后已经允许处理。美股收盘时香港常已是次日，手动报价表单也可能默认成错误日期。

修复后，服务端使用与实际操作相同的交易日历返回 `canCancel` / `canParentCancel`，页面直接据此展示按钮。标准交易日、港美半日市、两地时区都纳入回归。手动报价默认选择最早可处理订单的目标交易日。

相关文件：`lib/core.mjs` 的 `view()`、`public/app.js` 和两份 `final-*-audit.test.mjs`。

另同步修正部署指南关于自动顺延的旧描述。

## 建议的部署验收

使用完整源码连接 Netlify，按 `docs/NETLIFY.md` 配置 `DATABASE_URL`、`SETUP_TOKEN`，并根据现有 TLS 方案配置可选 `DATABASE_CA_CERT`。已有账本继续使用原数据库和账户；先备份，避免重新初始化。

在独立测试账本完成以下检查后，再正式记入真实家庭备付资金：

1. 家长与 Olivia 分别登录；记入小额测试余额；刷新、重新登录、重新部署后数据仍在，两台设备看到一致余额。
2. 跑通“购物申请 → 家长确认 → 申请退款 → 家长同意”，以及“借款 → 批准 → 全部还清”，核对扣款和退款各一次。
3. 搜索港美股票，点“抓取日线并结算”，检查报价日期；在 Netlify 的 `daily-settlement` 函数页面执行 **Run now**，再查看一次正常计划运行日志。
4. 在常用 iPhone / iPad Safari 检查登录、导航、金额输入、头像与确认弹窗。

Netlify 的计划任务只在已发布部署上按时间触发，预览部署可手动 Run now；本项目配置是香港时间 **17:30、06:30**。[Netlify 官方说明](https://docs.netlify.com/build/functions/scheduled-functions/)（本轮核查）。

## 保留的产品边界

- 金额展示一位小数，实际账务按分保存；“全部还清”由后台计算精确应还金额。
- 股票按合格收盘价模拟成交，美股固定 USD 1 = O$8；不是实时外汇换算。
- 非港美股票为自选观察，不会执行真实证券买卖。
- 分红、拆合股、代码变更等公司行动没有自动处理。发生时需要单独核对持仓数量、成本和估值；不能把公司行动造成的价格跳变直接理解为投资盈亏。
- 自动顺延依据所取得的日线。如果 Yahoo 漏掉正常交易日，系统无法凭缺失数据区分停牌和供应商漏报，可能使用更晚的首个可用收盘价。两年以上完全停用后恢复也应人工核对老的待成交订单，不能假定两年接口覆盖所有历史。
- 日历规则能覆盖目前内置和推算的常见安排；交易所临时改变收市时间等特殊情形仍需核对。

以上边界没有因本次修复扩大。对当前家庭银行用途，建议用本版进入部署验收，不再为了上线前检查追加新功能。
