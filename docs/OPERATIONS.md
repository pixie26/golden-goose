# 日常使用、升级与备份

适用版本：金鹅银行 **V2.0.3**。它承接 V2.0.2 / V2.0.1 / V2.0.0 / V1.0.3（开发版 V1.9.10 之后重新计数）；现有 `schema: 2` 账本保持兼容，不需要重新开户。

## 1. 启动与账户

本地推荐使用 Node.js 24（最低 22.8），在项目根目录执行：

```bash
npm ci
npm run dev
```

打开终端显示的网址，默认是 `http://localhost:3000`。首次创建银行时设置家长密码和 Olivia 的 PIN；本地默认初始化密钥为 `local-setup`。可参考 `.env.example` 创建自己的 `.env`，启动命令会自动读取。正式环境使用独立的初始化密钥和数据库配置，部署步骤见 [NETLIFY.md](NETLIFY.md)。

未配置 `DATABASE_URL` 时，数据保存在项目的 `data/bank.local.json`；配置后使用 PostgreSQL。重新启动、更新代码或更换网页资源不会自行清空账本。已有账户应直接登录，突然出现初始化界面时，先检查数据路径和数据库连接，不要立即创建新账户。

**本地文件模式只运行一个服务实例。** 它有单进程内的写入队列和原子保存，但没有跨进程文件锁。家人可通过同一个本地服务使用银行，不要启动多个服务共同写同一份 JSON。正式 PostgreSQL 模式通过事务和行锁处理并发。

## 2. 日常业务规则

- **货币与余额：** O$ 与港币按 1:1 约定。金额统一显示一位小数，内部现金账务精确到分；利息计算保留更高精度，结算时落到分。显示四舍五入不会修改实际余额，“全部还清”由服务器计算准确金额。
- **入账与消费：** 家长在对应资金准备好后直接入账。Olivia 提交购物申请时先预留金额，家长确认购买并交付后一次性扣款；拒绝后释放预留。购物和股票买单共用可用余额，定存及还款也不能占用已预留资金。
- **退款：** 已完成购买可在购买后七天内申请一次退款，以页面截止时间为准；提交后不能撤回，也不能在拒绝后重新申请。家长在“待处理”选择同意或拒绝，同意后原购买金额回到活期。升级旧订单不会重新开始七天期限。
- **定存与借款：** 定存开放三、六、十二个月，提前赎回只退本金，到期结算连本带息回活期。借款需家长批准，默认总额度 O$ 500.0，可在设置调整；未还本金与待批申请共同占用额度。借款按香港日期计息，还款先还利息。还款与应还金额相差不足 O$ 0.1 时忽略差额：多付的零头不扣，还款后余下不足 O$ 0.1 视为还清，免还金额记在借款记录（`waivedCents`）、流水说明和审计（`loan.waive`）中；每笔借款最多免还 O$ 0.09。新利率适用于之后的新定存或借款申请，已有记录沿用原利率。
- **任务与心愿：** 家长可创建、改价或暂停任务；已提交的任务记录保留提交时单价，验收后才发奖励。Olivia 可提议任务。达到目标的心愿可提交购买申请，仍需家长确认。

家长待处理清单、家长任务管理、待成交订单、定存、借款和心愿默认显示全部时间，其他有时间筛选的记录通常默认最近三十天，每页十条。可做任务清单不设筛选。找不到旧记录时先切换“全部时间”。申请处理结果通过 Olivia 页面的消息红点提示；这属于站内通知，不是短信或手机推送。

## 3. 股票记账与行情范围

应用支持最多十只自选股。Yahoo 搜索可查询多个市场；实际模拟买卖限港股 HKD 和美股 USD 股票或 ETF，美股按固定 **USD 1 = O$ 8** 记账。

**成交规则：每笔订单按下单之后的第一个收盘价成交。** 开盘前或盘中提交的订单使用当日收盘价；收盘后、周末或休市提交的订单使用下一交易日收盘价。港股、美股平时都在当地 16:00 收市，半日市港股 12:00、美股 13:00 收市。成交日收市前 Olivia 可以撤单，冻结的资金或股票退回。

收市 1 小时后才把 Yahoo 日线当作确认的收盘价。正式网站每天香港时间 17:30（港股已收市）和 06:30（美股已收市）自动抓取并结算，每次都会重试所有待成交订单；家长也可在后台随时“抓取日线并结算”。买入股数 = 冻结金额 ÷（收盘价 × 汇率），保留 6 位小数并向下取整，实际扣款向上取整到分，用不完的部分退回；卖出所得向下取整到分，按平均成本计算盈亏，不足一分时取消该笔订单并保留持仓。同一证券按成交日和提交先后依次结算，其他证券互不影响。

**成交日没有收盘价时：** 如果该股票之后已经出现收盘价，说明成交日当天没有交易（日历不知道的假期、临时休市或停牌），订单自动按之后第一个收盘价成交，订单上会显示“原定 X 休市或无收盘价，已顺延”。这与日历一开始就知道当天休市的结果完全相同，使用的价格也一定是下单之后才公布的。如果之后还没有任何收盘价（例如当晚 Yahoo 行情迟到），订单继续等待，不会提前顺延。

**卡住的订单：** 股票退市或长期停牌、一直没有收盘价时，家长可在成交日收市后在「股票」页撤销订单。买单退回预留资金，卖单解冻股票，Olivia 会收到站内通知。

**手动登记收盘价：** 只在 Yahoo 长时间抓取失败时使用，而且要从最早缺价的交易日开始逐日登记。登记较晚日期的价格后，更早缺价的订单会按这个较晚的价格成交，因为系统会把它当作“之后已有收盘价”。表单会默认填入最早缺价的股票和日期。Yahoo 是非官方行情来源，可能延迟、限流或不可用。自选收益仅反映价格变化，不包含股息。

**交易日历不需要每年更新。** 港股 2026–2027、美股 2026–2028 使用交易所公布的名单。之后的年份：美股按 NYSE 固定规则计算全部休市日和 13:00 提前收市；港股按规则计算平安夜、除夕和农历年三十的半日市，农历新年日期内置到 2099 年。港股 2028 年起的全日假期和任何临时休市不需要维护，都由上面的自动顺延处理，成交价不受影响，只有两处小差别：订单会先显示那个实际休市的日子为成交日，以及当天 16:00 后 Olivia 不能再撤单。交易所以后若改变半日市安排而规则没有覆盖，当天下午的订单可能按中午已经公布的收盘价成交；这只影响个别订单，不会造成账目错误。

尚未自动处理分红、拆股、合股、退市及其他公司行动。遇到这些情况，应先停止该证券的新申请，并请维护人员核对持仓和估值。本应用是家庭账本与投资学习工具，不会向券商下真实订单，也不会发起银行付款。

## 4. 网络异常时怎么处理

遇到超时或“尚未确认操作结果”，先查看流水、订单或审批状态，确认是否已经完成。优先保留当前标签页，用原输入重试；不要连续改写金额重新提交。系统会复用未确认请求的标识，避免重复入账或扣款。

同一标签页刷新后可恢复未确认请求，浏览器只保存摘要和随机标识，不保存完整业务内容或密码。此保护依赖浏览器存储及加密能力；明确退出、换设备或清除浏览器数据后，应先核对记录。收到“操作已完成，账户数据暂未刷新”时只需刷新账户。

Yahoo 若把旧代码返回为另一代码，系统会要求重新搜索并核对，不会静默建立别名账本。已登记证券的行情代码、币种或市场不符时，拒绝导入并保持订单待成交；请家长核对是否发生代码变更或公司行动。

新增股票后若账户刷新失败，页面保留原先选择，待恢复后才允许提交该股票的买入；恢复过程中不会自动改选另一只股票。

同一浏览器多个标签页共享登录 cookie。另一页切换了家长/Olivia 账户后，旧页面会要求重新登录，避免以错误身份提交。

## 5. 备份与恢复

**本地：** 先停止银行服务，再复制整个 `data` 目录到带日期的备份位置。若设置了 `BANK_DATA_FILE`，备份该实际文件。另行保管 `.env` 配置；不要把账本或密码配置提交到公开仓库。升级前、重要操作后保留一份备份，并定期确认备份可读取。

恢复时先停服，保留当前账本副本，再由维护人员把确认无误的备份放回原路径并启动，核对余额、持仓、借款及最近流水。恢复旧备份会丢失备份后的变更，需先做好对账。

**正式 PostgreSQL：** 使用数据库服务商提供的备份、快照或导出能力，确认保留期限并安排恢复演练。备份范围应包含完整 `bank_state` 账本及必要配置；生产数据恢复前先在独立数据库验证。应用目前没有内置的一键导出、导入或恢复功能。部署代码也不会自动搬迁本地 JSON 账本。

## 6. 升级与回退

升级前备份并记录现金、预留、定存、借款和股票持仓。替换应用代码时保留原账本、原数据库及账户凭据，再运行 `npm ci`、`npm run verify`，启动后核对上述记录；沿用现有账户，不重新初始化。

### 从 V2.0.2 升级到 V2.0.3

先备份账本，再替换代码并重新部署。账户、`schema: 2`、数据库和初始化密钥继续沿用。修复不改变现金、持仓、定存或借款的计算方式。

如果已经添加英国等海外自选，下一次成功的 Yahoo 历史行情刷新会把旧版误大写的 `GBP` / `ZAC` 恢复为供应商实际返回的 `GBp` / `ZAc`；只改单位标签，不缩放任何历史数值。新核验的单位会记录 `quoteUnitVerified`，之后若供应商改变单位则继续按身份冲突阻止混用。

定存到期而计划任务尚未执行时，页面会显示“到期取回”；家长收盘后处理待成交订单的按钮也与后台权限一致。升级前已打开的页面建议刷新一次以加载新界面。

### 从 V2.0.1 升级到 V2.0.2

无数据迁移。替换代码、`npm ci`、`npm run verify` 后部署，沿用原数据库和定时任务。升级后的第一次结算会按新规则处理所有待成交订单：成交日已过、当天没有收盘价、但之后已有收盘价的订单会立即按之后第一个收盘价成交；旧版“请先补齐该交易日行情”的提示会自动清除。若升级前有订单因缺价被家长刻意保留，等待补登当天价格，请先补登再部署。

### 从 V1.0.3 升级到 V2.0.0

无数据迁移。替换代码、`npm ci`、`npm run verify` 后部署，沿用原数据库。部署后第一次打开页面时，每个函数实例会读取一次完整账本，之后只在账本变化时重新读取。旧的结算报价会在下一次行情更新时按 125 天窗口自动修剪，已成交记录、持仓估值和涨跌表现不受影响。

### 从 V1.0.2 及以前版本升级的股票核对

V1.0.3 起修复的是仍待成交订单的执行顺序，不会自动改写已成交历史。若检测到某笔待成交单应早于同股已成交记录，系统会保留预留金额并暂停该证券后续结算，在订单上提示家长核对历史成本；其他证券继续处理。调整交易日也不能把订单移到已成交记录之前。若此前发生过同一证券跨日订单一起补行情，或先处理晚一天报价、后补早一天报价，请在开放该证券继续交易前核对持仓成本与已实现盈亏。现金和股数可能完全正确，但成本仍有错误。

若确认受影响，先备份，再根据完整成交记录按交易日和提交顺序重算成本及盈亏。不要重放入账、买卖或退款操作来补差额，也不要只改页面上的显示值。早期版本若已截断成交历史，应先取得原始备份；不能仅凭当前余额推算成本。未使用过股票交易的新账本无需这项历史处理。

网页版本回退不等于账本回退。不能直接退回会截断历史记录或删除旧请求标识的开发版，否则可能丢失流水并削弱重复请求保护。需要回退时，先备份当前生产账本，由维护人员确认代码与数据兼容，并保留回退期间的完整对账记录。
