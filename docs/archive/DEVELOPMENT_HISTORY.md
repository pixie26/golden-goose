# V1.1 — 简化存钱与定期操作

- **取消存钱申请**：Olivia 不再向爸爸提交“存钱申请”。只有爸爸可以在后台直接记录外部新增资金；已有资金不需要爸爸再次确认。
- **定期开户自主操作**：Olivia 从可用活期余额转入 3/6/12 个月定期，立即生效并锁定利率，不需要审批。
- **提前赎回自主操作**：Olivia 点击“提前赎回”并确认，即刻退还本金至活期，利息为 0；无需审批。若实际已到期但尚未运行自动结算，此操作将正常执行到期本息结算，避免误扣已到期利息。
- **保留审批**：购买物品、向爸爸借款仍须审批；股票买卖不需要家长审批。
- **兼容旧数据**：如果早期本地账本存在待处理存钱申请，爸爸后台会出现仅用于旧记录处理的区域；不再创建新的存钱申请。
- **升级说明**：若已使用 V1，请先备份 `data/bank.local.json`，再用 V1.1 文件替换程序目录，保留原 data/ 文件夹。

本地运行：Node.js 22+，`npm run dev`，打开 http://localhost:3000 。

# 皇家金鹅银行 V1.2 — 股票市场与自选股升级

## 1. 股票交易目标价

- 港美股股票下单的目标日依据**提交订单时**的交易所本地时间：开盘前、盘中提交 → 该交易日收盘价；该交易日收盘后或节假日 → 下一交易日收盘价。
- 香港使用 Asia/Hong_Kong；纽约使用 America/New_York，自动适配夏令时。
- HKEX 股票市场 2026/2027 官方节假日及半日市、NYSE 2026/2027/2028 已公布节假日及提前收市日已经列入日历。
- 明确排除未收盘时 Yahoo 返回的正在进行中的日线数据。收盘以后另预留 5 分钟确认窗口，保证不会把盘中报价当最终收盘价。
- 只有**目标日完全一致**且明确验证为已完成的最终收盘数据可成交。旧版遗留的未经确认报价不会直接用于结算，需重新抓取或手动核验收盘价。正常交易日如果行情缺失，订单保持待成交，不能使用更晚的价替代。
- V1.1 的历史 pending 订单默认不自动更改；爸爸后台增加“按原提交时间重算”按钮，手动重算旧订单目标日。

## 2. Yahoo 股票搜索

- 股票名称、中文或英文、股票代码均可模糊搜索 Yahoo Finance。加入交易列表前后端再次从 Yahoo 核实证券身份、交易所及货币，防止假代码或错误的 FX。
- 不再只有7只预选股票。港股 HKD 和美股 USD 股票 / ETF 支持真实资金背书的模拟买卖；其他 Yahoo 股票可以观察价格，但没有给定合理 FX 规则前暂不开放交易。
- Yahoo 为非官方免费接口，需要互联网、可能被限流或屏蔽。不代表 Yahoo 官方数据授权或可靠性保证。

## 3. 自选股最多10只

- 加入或移除自选，不影响原有持仓和资金。
- 每只显示最近已完成的收盘价、币种、市场日期；1D 与上一交易日收盘比较、1W 与5个交易日前比较、YTD 与上一年最后一个交易日收盘比较。
- YTD、周涨跌使用历史收盘数据，只统计价格变化（不是含分红总回报），历史不足显示“—”。
- 数据存储本地 data/bank.local.json 或正式 PostgreSQL（按照现有部署环境）。

## 4. 兼容

保留 V1.1 的 PIN/密码、购物审批、定期年息5/8/10、提前赎回无利息、爸爸借款上限O$500和默认年息25%，O$与港币1:1，美股固定USD:O$=1:8。

## 5. 验证

- `npm run check` 检查 JavaScript 语法。
- `npm test` 运行账务、交易日/早收市、行情完结判断、跟踪股涨跌、API 权限与历史数据的自动化测试。
- 版本包未包含任何正式或原 ChatGPT Site 的客户/家庭资金数据，首次运行余额从 O$0 开始。

# V1.5 更新说明 — 任务赚钱 + 金额显示精简

## 新增任务赚钱

- 爸爸可以新增、修改、暂停和恢复任务。任务名称、计价单位（件、次、本）和单价可在家长后台修改。
- 例如「叠衬衫，每件 O$2」，Olivia 完成 5 件后申请验收，爸爸批准后一次性获得 **O$10**。
- Olivia 可以自行提议新的任务和每单位奖励，由爸爸批准或拒绝。批准任务并不会立即发放奖励。
- Olivia 提交完成数量后，爸爸须先验收，奖励才进入活期账户并写入流水。爸爸可以拒绝未完成的任务。
- 已经提交的完成记录锁定当时的奖励单价；爸爸后来改价不会追溯修改旧记录。
- 任务奖励单价必须是整数 O$，完成数量也必须是整数。拒绝和重复审批都不会重复发钱。

## 金额展示

- 普通存款、购物、借款、任务奖励：**整数优先**，例如 O$170、O$2。
- 股票市值、持仓收益、首页总资产/净资产：**一位小数**，例如 O$1,280.5。
- 少于 O$0.1 的非零小额结算可例外显示两位小数，避免显示 O$0。
- 股票价格通常显示一位小数；小于 1 元的低价证券保留三位小数，避免显示为 0.0。系统内部继续精确记账，不因为界面四舍五入而改变余额。
- 删除页面中 O$ 与 HKD 固定汇率的提示；内部规则不变。股票美元估值仍采用之前约定的 1:8 固定换算。

## 升级与兼容

- V1.4 本地账户无需重建。旧数据无任务字段时自动显示空列表，爸爸可创建第一项任务。
- 升级之前请备份 `data/bank.local.json`；**不要将此文件上传到公开 GitHub 仓库**。
- 该网站用于家庭内部记账，不涉及真正银行汇款或券商交易。

# V1.6 更新｜网络搜索诊断、购物确认即交付、退货退款

## 1. Yahoo 搜索出现 `fetch failed`

V1.5 会把服务器端连接失败的原始信息直接传到儿童页面。V1.6 捕捉并分类网络连接失败（DNS、超时、403、429 等），首先尝试 Yahoo 的 query2/query1，再显示清晰的离线提示。

断网时可以通过一小组预置股票和 ETF 搜索并添加已知标的，例如 TSLA、AAPL、NVDA、0700.HK；这**不是** Yahoo 完整证券池。行情和涨跌幅未获取到时显示缺失，**不生成虚拟报价**，已有订单保持目标交易日待成交。

如果 Yahoo 恢复可用，继续使用原有的模糊搜索及官方交易日校验规则，港美股按原来的日频收盘价结算。

## 2. 购物一次确认并交付

- Olivia 申请时不扣款。
- 爸爸实际购买并交付后，只点击一次「确认购买并交付（扣款）」：同时完成确认/交付及扣款，保证账本仅记录一次。
- 删除 V1.5 的「待交付」二次确认按钮，爸爸仍可拒绝申请。

## 3. 退货与退款

- Olivia 对已购买商品可提交退货申请及原因，或在未审批前撤回退货申请。
- 爸爸可确认实际收到退货后直接退款，恢复全部原购买金额到活期；也可拒绝退货，不影响余额。
- 爸爸可对已购买订单直接执行全额退货退款。不可重复退款。
- V1.5 中 `approved` 但已扣钱的旧订单，升级后可直接退款；不会重复扣款。

## 4. 金额展示和兼容

所有 O$ 金额显示保留一位小数，不改变内部账本精度。升级前备份旧版的 `data/bank.local.json`，然后原样保留数据文件。

## CHANGELOG_V1.9.3_功能优化与修复

# V1.9.3 — 可用资金、记录整理、心愿购买与表单修复

## 1. 买股票与购物申请共用可用金额

可用金额按「活期现金 − 股票买单预留 − 购物申请预留」计算，不包含未赎回定期和未卖出股票的市值。

- 申请购买与买入股票的输入框展示本次最多可用金额，并设置输入上限。
- 服务端再次校验资金。两个页面或设备同时申请时，仍由原有持久化事务串行检查，不能重复使用同一笔钱。
- 新购物申请提交后预留预算；活期现金和总资产暂不减少，可用金额减少。
- 家长确认购买并交付时才扣款；可以使用这张申请本身已经预留的资金。批准价格低于申请价格时，释放差额。
- 拒绝购物申请后释放预留。股票买单撤销后，仍按原规则释放股票预留。
- 开定期和还款也使用更新后的可用金额，避免使用已预留给购物的钱。

例如：活期 O$162.0，提交 O$123.0 的购物申请后，活期仍是 O$162.0，购物预留 O$123.0，可用 O$39.0。此时不能再提交 O$40.0 的购物或股票买单。家长拒绝后，可用金额回到 O$162.0；家长确认购买后，活期与可用金额均为 O$39.0。

### 旧数据兼容

旧版待处理购物申请没有预留字段，升级时不追溯冻结这些申请，以免历史申请总额超过现金而使账户不可用。旧申请批准时仍会检查实时可用金额，并保护新版申请的预留资金。从本版新提交的申请开始预留。

## 2. 分类、时间与每页 10 条

以下列表增加独立分页与条数提示：购物、股票订单、股票持仓、任务清单、任务提议、任务收入、现金流水、定期、借款、心愿，以及家长后台的对应记录。

- 默认最新在前；按日期记录的列表可切换最早在前。
- 支持状态或类型分类，例如待处理、已购买、未通过、已退款，以及交易流水类型。持仓按市场分类。
- 有日期的列表支持全部时间、最近 7 天、最近 30 天、本月。
- 每页最多 10 条，显示当前范围、总条数、页码、上一页和下一页。
- 筛选后回到第一页，记录减少时自动修正页码。
- 去掉购物、股票、任务旧版只展示 15／20／30 条的页面截断；现金流水 API 不再仅返回前 150 条。
- 翻页仅更新对应列表，不刷新旁边正在填写的表单；列表内部的任务数量、备注、还款和编辑字段在翻页期间保存在内存，回到该页可继续填写。不会将密码或 PIN 保存为草稿。
- 首页的简短摘要和最下方自选股继续保留原有布局。

分页只控制展示，不删除数据。底层原有保留策略未改变：现金流水最多保留 3000 条，审计最多 1200 条；本版可翻看当前仍保存在数据文件或数据库内的记录，不能找回以前已经被旧版截掉的数据。

## 3. 心愿达标后，一键申请购买

- 心愿允许设定高于当前可用金额的目标。

## CHANGELOG_V1.9.5_退款借款与稳定性

# V1.9.5 — 退款规则、借款限额与稳定性

## 1. 登录名称

## 2. 购买后 7 天内，只能申请一次退款

- 退款申请期限为购买完成后 7 × 24 小时，服务器按原购买时间核对。
- 每笔订单只能申请一次，提交后不能撤回；家长拒绝后也不能再次申请。

- 同意退款后，全额原购买金额退回 Olivia 的活期账户，只有一笔退款流水；重复提交同一请求不会重复入账。拒绝不改变余额。

## 4. 「全部还清」与读取异常

检查发现，原前端把「操作请求已经成功、随后刷新账户失败」也统一显示为操作失败。本版区分这两种状态：操作成功后如刷新失败，提示刷新账户，刷新只读取状态，不重复提交扣款。

「全部还清」继续由服务端计算当日计息后的精确应还金额，按分偿还，不使用界面四舍五入后的数值。请求幂等保护继续防止重复记账。

用户提到的原始 `Unterminated string in JSON` 更符合本地账本读取异常；还款函数本身不解析 JSON，而请求体解析错误已有独立提示。没有现场账本与日志，无法确认该次错误的精确根因。本版同时加固相关路径：

- 本地 JSON 解析失败时短暂重读，最多 3 次，两次等待合计 100ms；仅重读文件，不重试财务操作。
- 持续读取失败返回中文提示和 `BANK_STORE_UNREADABLE`，保留原文件，不重置为空账户或截断修复。
- 保存使用独立随机临时文件，排他创建，完成写入和同步后再原子替换；失败清理临时文件。
- 账户刷新等待此前已入队的本地操作完成。
- PostgreSQL 事务与行锁机制继续沿用。

## 5. 可调整 Olivia 的借款限额

家长在后台设置中修改借款限额，默认 O$500。设为 0 可暂停新增借款和待审批借款的发放。

剩余额度 = 配置限额 − 未还本金 − 全部待审批借款金额，最低为 0。提交和批准时均由服务端检查，避免连续多次申请后合计超过额度。拒绝待批借款会释放其占用的额度。

降低限额不会修改已有债务，也不会阻止偿还；额度不足时先还款、拒绝其他待批申请或提高额度。旧账户若已有有效配置继续沿用，缺少限额字段时默认 O$500。借款利率仍按原规则在申请时记录，已有借款不追溯改息。

## 6. 金额显示

金额按实际数值最多保留一位小数，整数不强行补 `.0`：

| 账本金额 | 界面显示 |
| --- | --- |
| 162.00 | O$162 |

这只是显示格式；账务仍以整数分保存，余额、退款、买卖和还款不会因显示而损失精度。

## 日期口径说明（第 1、2 项）

- 已有定期的起止日期不改写，利息仍按原起止日期之间的天数计算，金额不变；只是到期结算时间按香港日期提前，最多早约 8 小时。
