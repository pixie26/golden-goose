## 发布结论

**本轮发现并修复了 Yahoo 证券身份不一致的功能缺陷及错误行情导入风险；修订后未发现剩余的已知代码级上线阻断问题，可以进入 Netlify 实际部署验收。**

本轮没有发布网站、连接用户的 Netlify / Supabase 账号或修改个人账本。`schema: 2` 不变，旧账户和数据继续兼容。最终生产可用性仍需要在自己的部署中验证数据库连接、行情访问、定时任务及常用手机浏览器。

## 已修复问题

### 1. 股票代码发生重定向时无法完成选择

受控复现：请求旧代码 `FB`，Yahoo 元数据返回 `META`。原版 HTTP 返回成功，账本登记 `META`，但历史日线仍被归到 `FB` 而丢弃，前端还在等待 `FB`，因此该次买入选择无法完成。旧版保护阻止错买其他股票，但页面会卡住。

V2.0.1 明确拒绝不一致，提示重新搜索并核对实际代码。不会静默改选证券，也不会创建两套别名持仓。即使请求代码存在于离线目录，也不能把明确的身份冲突当作普通网络故障而回退成功。

### 2. 日线与已有证券身份不一致仍可能被导入

原版没有比对 Yahoo 返回的 `symbol`、`currency`、`exchangeTimezoneName`，异常响应可能被记录为原证券的行情，并按原证券币种用于待成交订单。

V2.0.1 对返回元数据与已登记证券进行校验；代码、币种或交易市场不符则不导入这一证券的行情、不据此成交，保留现金及冻结金额并向家长报告原因。其他证券的正常行情仍可保存及结算。

### 3. 发布整理

- 自选股说明明确“收益截至所示收盘日”，消除年初显示上一收盘年份 YTD 的口径歧义；不改收益计算。
- 修复 ZIP 中中文启动文件名的编码，并保留 Mac 启动脚本执行权限。
- 同步版本、锁文件和网页资源缓存标记为 2.0.1。
- 当前说明和证据留在 `docs/` / `docs/verification/`；旧版本资料按版本放入 `docs/archive/`。
- 按 [Netlify 官方文档](https://docs.netlify.com/build/functions/configuration/) 更正同步函数上限为 60 秒、定时函数为 30 秒。应用仍保留主动 7 秒 Yahoo 页面预算。

## 重点业务复核

资金核心未修改。本轮对以下既有行为的代码和回归检查通过：

- 购物及股票订单共用可用余额；开定存、还款不能占用已预留金额。
- 审批购物金额降低时释放差额；退款购买后七天内只可申请一次，拒绝后不能重申。
- 定存到期只入账一次；贷款本金与待批金额共同占用限额，“全部还清”按服务器的准确金额执行。
- 任务奖励保留提交时的单价；重复验收、重复入账、请求超时重试不重复记账。
- 同股票补历史行情按目标交易日及提交顺序成交；碎股舍入不会凭空增加现金。
- 子账户不能调用家长功能；更改密码 / PIN 后撤销对应会话；跨标签切换账户有角色校验。
- 损坏本地账本不会被空账本覆盖；数据库失败和不确定提交不会自动重放资金操作。
- 定存、借款、心愿、家长待办与任务管理、家长待成交订单默认全部时间，其余历史默认三十天、每页十条。

## 部署后完成这五项验收

1. **环境与登录：** 完整源码通过 Git 连接部署，配置 Functions 范围的 `DATABASE_URL`、`SETUP_TOKEN`，按所选 TLS 模式配置 `DATABASE_CA_CERT`；家长、Olivia 分别登录退出。
2. **持久化与同步：** 在独立测试库记一笔小额入账，刷新、重新登录及重新部署后仍存在；两台设备能看到同一账本变化。
3. **完整资金流程：** 测试库完成购物申请 → 家长批准 → 申请退款 → 家长批准，以及借款 → 全部还清；核对余额、预留及流水各发生一次。
4. **行情与计划任务：** 搜索港股 / 美股，核对返回代码和报价日期；执行家长“抓取日线并结算”，在 Netlify 对 `daily-settlement` 使用 Run now，再观察计划执行日志。缺少目标日行情时应继续待成交，不使用其他日期替代。
5. **常用设备：** 用实际 iPhone / iPad 检查登录、输入、导航、五个家长分页、头像上传及弹窗。

生产账本只记真实备付资金；以上演练优先用独立测试数据库。已有账本直接沿用，不要重新初始化。
